# smarticd10 搜尋對照與離線實作（0.2.4）

## 來源及核對範圍

觀察時間：2026-10-31。使用[smarticd10](https://smarticd10.health.belgium.be/default.php)公開介面、頁面請求及公開JavaScript判讀，不宣稱取得PHP後端程式。只使用一般查詢請求，沒有登入、權限繞過或病歷資料。

App資料：使用者`官方資料/CMS-ICD-10-CM-2025.icdpack`，實際manifest為`FY2025 / 2025-04-01`，不是僅依檔名推測。原包SHA256：`55a7b7660f153836b0b39b040c4dbf3fda6b5726d1ef303ec2e2829a7be392d1`。網站只標2025，未提供同等半年度manifest；其他查詢不能僅因FY相同就保證一模一樣。

網站不是App資料來源；原始HTML／JS對照只存`.local-source/`，不隨App、資料包或備份再散布。App繼續只讀官方SQLite，沒有新增網路功能或改寫資料包。

## 為何原本不同

| 0.2.3行為 | 網站可觀察行為 | 0.2.4實作 |
|---|---|---|
| Tabular結果先填入，再接Index | 英文詞彙主要導向Index | 有Index的CM預設「索引導引」，代碼精確查詢仍優先 |
| 各來源以BM25相關度排序 | Index按主詞／子詞與原始書目順序呈現 | 用FTS5找候選，但不以BM25重排；按來源display_order排序 |
| Index扁平化且最多100筆 | 保留上層脈絡與完整分支 | SQL遞迴補回祖先、保留父子關係；每頁100筆，可繼續載入 |
| 短詞也在所有路徑做全文查詢 | 單一詞即時輸入提供主詞前綴建議，送出才查完整路徑 | 即時主詞建議／點選完整分支／Enter送出查詢；多詞直接查脈絡 |

例：舊App輸入`Diabetes, diabetic`時，先看到E10.21等Tabular描述；新模式先看到Index主詞與其E11.9目標，再依官方順序呈現修飾詞。目標碼只是Index的來源指向，不等於病人診斷或申報建議。

## 詞彙與排序規則

1. 搜尋採大小寫不敏感的英數詞首比對，逗號等標點用於分詞；AND表示所有詞須在同一完整來源路徑出現，順序不影響命中。保留原AND／OR及前綴開關，不將字串直接當SQL／FTS指令。
2. 查完整Index路徑，不是先把英文翻成同義詞或診斷；不把cross-reference目標文字混入搜尋欄位。see／see also仍在原節點詳情保留，點選可續查。
3. 將命中節點的所有上層一併顯示，再依來源順序排列；以節點ID去重，不能以目標碼去重，因不同修飾詞可指向同一碼。
4. 所有顯示名稱、修飾詞、原文與來源關係仍取自官方包；不模仿網站移動非必要修飾詞、補空白或重組原文。保留未完整碼與cross-reference的既有警示。
5. CM「全部」在導引模式查CM各Index，按Alphabetic／Neoplasm／Drugs／External分組及來源順序；指定分類可只查該Index。關閉「索引導引」即可使用舊Tabular＋Index全文相關度；選Tabular直接查代碼表。
6. NHI中英對照包未提供Index時，自動維持原代碼／英文／中文查詢，不生成假Index。中文索引、跨版中譯政策及PCS七軸語義不變。

## 實際對照

以下網站數為畫面Index節點數（含上層脈絡），不是確立診斷數：

| 查詢 | 網站2025 Diseases | App FY2025 Apr導引 | 說明 |
|---|---:|---:|---|
| Diabetes, diabetic | 449 | 449 | 全部449個位置的目標碼序列逐筆相同；含沒有精確碼的節點 |
| diabetes diabetic | 449 | 449 | 逗號不改變詞彙命中 |
| diabetic diabetes | 449 | 449 | AND不依輸入詞序 |
| diabetes kidney | 24 | 24 | 保留必要祖先 |
| kidney diabetes | 24 | 24 | 同上 |
| diab neph | 34 | 34 | 詞首，不是任意子字串 |
| betes | 0 | 0 | 不從diabetes字中間命中 |
| diabetes type 1／type 2 | 兩者均230 | 依1／2分別過濾 | 刻意不複製網站對單字元數字未形成區分的觀察結果 |
| heart failure | 157 | 158 | 原官方XML有一個Note標題的來源節點；App保留而不刪除以湊數 |

單字元數字的處理是明確差異：網站`diabetes type`、`diabetes type 1`、`diabetes type 2`三種查詢皆230節點，且同時含E10／E11目標。本版保留數字詞，避免type 1與type 2失去區分。不能宣稱所有查詢與網站100%相同。

`heart failure`的差異已直接檢視官方XML：`Failure`下有一個title以`Note: heart failure stages...`開頭的實際term，且附帶stage等子詞；網站在heart路徑下重整顯示。這是來源／呈現差異，不改寫官方父子關係來強行一致。

## 操作

- 使用US CM FY2025包，保留「索引導引」及AND／前綴，輸入範例即可看到主詞、縮排及目標碼。
- 標示「已載入100／449筆」，捲到列表底部按「載入更多」；可繼續至449，不會只保留前100。
- 單詞即時輸入提供主詞建議，點主詞展開該來源分支；Enter查完整路徑。
- 點目標碼到Tabular核對；未完整碼／範圍不自動當成有效申報碼。
- 想看舊式英文描述相關度時，關閉「索引導引」或選Tabular。

## 驗證與限制

合成包回歸涵蓋：Index優先、BM25保留可選、來源順序、脈絡補回、跨頁不重不漏、相同目標碼不誤刪、數字1／2、主詞建議與分支、精確碼、無Index回退、安全分詞。手機／平板／桌面1.6倍文字的widget測試及Android隔離實測分開記錄；原生callback的操作與Future在runAsync生命週期內完成後才關閉資料庫。

完整FY2025包另用真實App repository驗證全部449節點、五頁查詢及多組對照，原包hash不變；實際結果與效能於[0.2.4驗收](RELEASE_0.2.4.md)補記。Windows CI只使用合成包，不把完整官方資料上傳。未執行的乾淨工作站／實體平板／全部版本資料驗收不得算通過。
